# JARVIS on Render — DM Responder, PWA & Push (deploy guide)

Deploy JARVIS as one free Render web service, install the dashboard as an
iPhone PWA, and let it answer your Messenger + Instagram DMs.

## 1. Deploy

1. In Render: **New → Web Service → Build and deploy from a Git repository**,
   pick `rayanhhhgfy-cyber/jarvis-ai`, branch `main`. Render detects
   `render.yaml` and fills in the build/start commands.
   (Or: **New → Blueprint**, same repo — the file is at the repo root.)
2. Wait for the first deploy to go live. Health check path is `/health`.

## 2. Environment variables (Render → service → Environment)

| Variable | Required | What it is |
|---|---|---|
| `BACKEND_SECRET_KEY` | Yes | Auto-generated by `render.yaml` (or paste your own 64-char secret). |
| `ENCRYPTION_KEY` | Yes | Auto-generated by `render.yaml` (Fernet key). Without it, stored credentials become unreadable after a restart. |
| `GROQ_API_KEY` | Yes for DMs | Free Groq key (console.groq.com, no card). Llama 3.3 70B is the DM brain. |
| `GEMINI_API_KEY` | Recommended | Free Google AI Studio key. Gemini 2.5 Flash is the automatic fallback when Groq is rate-limited. |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | Yes for push | Generate once (see §4). |
| `VAPID_CLAIMS_EMAIL` | No | Defaults to `sir@jarvis-omega.local`. |
| `DM_RESPONDER_ENABLED` | No | `false` by default. Set `true` only after you connect an account (§5). |
| `DM_POLL_INTERVAL_SECONDS` | No | `60` by default. |

Never put a real key, password or cookie in the repo, in chat, or in a
screenshot. Env vars are set in the Render dashboard only.

## 3. Keepalive — Render free sleeps after 15 minutes idle

Render's free tier spins a service down after 15 minutes without traffic,
and waking it takes 30–60 seconds. Keep it awake with a ping every
**10 minutes** (not 2 — 10 is enough, and 2 buys nothing):

* Use the cron-job.org job you already have (or create one): **GET
  `https://<your-app>.onrender.com/health` every 10 minutes.**
* The `/health` endpoint is lightweight and already exists.

Free-tier budget: 750 instance-hours/month per workspace. One service
awake 24/7 uses about 720 hours, so this service fits — but it is your
one always-on free service.

## 4. Push notifications (VAPID keys)

You never generate or touch the VAPID keys. **Muse generates the key
pair once at deploy time** (Python + pywebpush) and sets
`VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` in the Render dashboard
itself. The values never appear in chat, in screenshots, or in the
repo — only the variable names live in `render.yaml` / `.env.example`.

This is the exact same mechanism as future-thinkers notifications:
VAPID web push, same shape as its `push_routes.py` (subscribe /
unsubscribe / vapid-public-key), its `push.js` (service-worker
subscription) and its `sw.js` (push handler). Same behaviour, same
iPhone flow — nothing new to learn.

Then, on your iPhone:

1. Open the dashboard in Safari, **Share → Add to Home Screen**.
2. Open it from the Home Screen (this is what makes it a PWA).
3. Go to the **Connectors** tab → **Enable notifications** → Allow.
4. Tap **Send test notification** — it should arrive on your phone.

**iOS rule (Apple, not us):** web push on iPhone only works from a PWA
that was added to the Home Screen, on iOS 16.4 or later. In Safari
without adding it, the enable button will fail plainly.

## 4b. Split deploy — frontend on Vercel, backend on Render

The dashboard can also run split: static frontend on Vercel, FastAPI
backend on Render.

1. Deploy the backend to Render first (Blueprint, §1) and note its URL,
   e.g. `https://jarvis-ai.onrender.com`.
2. In `frontend/config.js`, set the one line the Vercel deploy must change:
   `window.JARVIS_API_URL = "https://jarvis-ai.onrender.com";`
   (no trailing slash). Empty means same-origin (Render all-in-one).
   The WebSocket follows the same host automatically (https → wss).
3. Deploy the frontend to Vercel with root directory `frontend`.
   `frontend/vercel.json` rewrites `/manifest.json`, `/sw.js` and
   `/icons/*` to the files under `frontend/pwa/`, and its build
   command runs `pwa/generate_icons.py` so the PWA icons exist as
   real static files (the repo carries no binary assets — the push
   path is UTF-8 only; the backend runtime generator stays as the
   fallback on Render).
4. On Render, set `BACKEND_CORS_ORIGINS` to a JSON list including the
   Vercel URL, e.g. `["https://jarvis-frontend.vercel.app"]`
   (use the real Vercel project URL). Without this, the Vercel
   frontend's API calls are rejected by the backend's CORS check.

## 5. Connect Messenger + Instagram (the Connectors tab)

1. Open the dashboard (from the Home Screen PWA) → **Connectors** tab.
2. Tap **Connect** on Messenger or Instagram. A form opens with two
   modes — pick one:
   * **Email + password**: your Facebook/Instagram login. Jarvis logs in
     as you and saves the session.
   * **Cookies**: paste a cookies export from a browser tab where you are
     already logged in (e.g. `c_user=...; xs=...` for Messenger,
     `sessionid=...` for Instagram).
3. Jarvis verifies the login first. Only a verified login is stored,
   encrypted. A failed or challenged login stores nothing.
4. Set `DM_RESPONDER_ENABLED=true` in Render and redeploy (or restart).
   Jarvis then polls each connected account about once a minute and
   replies to new one-to-one DMs as you, in Jordanian Arabic/English.

## 6. Honest warnings — read before you connect

* **Against the platforms' rules.** Automating a personal Messenger or
  Instagram account violates Meta's terms. Your account can be locked,
  challenged, or banned. Instagram is the strictest: it often interrupts
  a login with a "verification code" challenge, and when that happens
  the bot stops until you approve the login in the app and reconnect
  with fresh cookies.
* **Ephemeral disk.** Render's free tier has no persistent disk. The
  encrypted vault file (`storage/connectors.json`) lives on the
  container's disk — a redeploy or a Render-side restart wipes it, and
  you will need to reconnect in the Connectors tab (30 seconds).
  Subscriptions and seen-DM state live in the same place and are wiped
  the same way.
* **Replies are one-to-one only, max 5 per poll.** Jarvis never replies
  in group chats and never replies to your own messages.
* **The Messenger client is best-effort.** It drives Meta's undocumented
  web endpoints (grounded in the public facebook-chat-api project). If
  Meta changes those endpoints, Messenger polling degrades loudly in
  status instead of silently pretending to work; Instagram runs on the
  maintained `instagrapi` library.
* **Free LLM limits.** Groq's free tier for Llama 3.3 70B is 1,000
  requests/day; Gemini 2.5 Flash is a few hundred a day depending on
  the account. A DM turn is one request, so normal use fits easily.
